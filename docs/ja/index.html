0.2.0 の新機能

Hive City。
クルーが小さな街になります。

hivedesk は小さな街から始まるようになりました。あなたのPCは部屋のある建物で、エージェントはそこに住み、すべてのタスクは部屋を通って完了へ向かいます。友だちは6つの単語で参加し、自分のマシンも連れてきます。

街がそのままシステムの状態です。 それぞれの部屋は、使えるツールが決まった本物の作業場所です。タスクボードには、すべてのタスクと今いるループが表示されます。

友だちは建物です。 友だちが Code together の6つの単語で参加すると、そのマシンがあなたの隣に建ち上がります。GPU、モデル、そこに住むエージェントも一緒です。

GPUを借りる、制限つきで。 エージェントは友だちのマシンにターン数と分数を指定して頼みます。貸す側は承諾するか、制限を下げるか、断れます。ターンはすべて数えられ、どちらからでも止められ、やり取りされるのはプロンプトと回答だけです。

Design、Code、Review、Test。 別のエージェントが基準に照らして差分をレビューし、そのあとチェックが走ります。失敗すると問題点とともに作成者へ戻り、最大3回まで繰り返したあとタスクはブロックされます。どの段階でも承認または差し戻しができます。

ずっといるエージェント。 各エージェントには、仕事で得たレベルとXP、ツール、編集やピン留めができる自分だけのメモリがあります。すべてあなたのマシンに保存されるので、明日も同じエージェントが戻ってきて、終わっていないタスクがまた開きます。

ずっといるエージェント

クルーのワーカーはそれぞれエージェントで、ホームの部屋、レベルとXP(作業で10、レビューで4、テストで3、ループなしで終わったタスクはさらに5)、ツール、最大40件の短い記録を持つメモリがあります。

ルールのある部屋

Lobby、Design、Code、Review、Test、Ops、Library。エージェントが部屋で作業している間、使えるツールはその部屋のものに絞られます。Ops はホスト専用で、拡張機能で部屋を追加することもできます。

タスクバス

タスクはあなたから、Mel の計画から、または作業を差し戻すエージェントから届きます。手の空いたエージェントはスキル、レベル、マシンの負荷で入札します。担当、受け渡し、判定はすべてイベントとして再生できます。

ゲストがいても安全

マシン、エージェント、タスクの持ち主の判断が優先されます。ゲストのタスクは承認モードがオンの状態で動き、コマンドも削除もできず、Ops では決して実行されません。以前のデスクトップがいい場合は --no-city で起動してください。

npx hivedesk --demo の実際のスクリーンショットです。街のシナリオを再生します: 友だちが6つの単語で参加し、Dev が彼女のGPUを3ターン借り、タスクが Design、Code、Review、Test を経て完了します。デモのイベントにはすべてラベルがついています。まだできないこと: Test が実行するのは静的チェック(HTML、リンク、JSの構文、CSS、JSON)で、あなた自身のテストスイートではありません。また貸し借りはリクエストごとの制限つきで、常時の共有ではありません。

映像

    動作環境

    • Windows、macOS、Linux 上の Node.js 20 以降。
    • ディスク: モデル用に0.5から9.0 GB、加えてランタイム用に最大約0.7 GB、初回のみ。
    • 読み込みに必要な空きRAM: モデルをGPUに載せる場合は2.5 GB、CPUの場合はモデルのサイズに1.5 GBを足した量(最低4 GB)。足りない場合は読み込まないので、マシンが固まることはありません。
    • GPUはなくても大丈夫: 最近のグラフィックカードの多くで動き、Apple Silicon でも動きます。
    • 初回起動時は ネットワーク が必要です。モデルの入ったローカルのランタイムがすでに動いていれば、それを使ってダウンロードを省きます。

    どのモデルになるか

    あなたのハードウェアモデルダウンロード実行場所
    VRAM 10 GB以上のGPU14B9.0 GBGPU
    VRAM 7から10 GBのGPU7B4.7 GBGPU
    VRAM 4から7 GBのGPU(例: 6 GBのカード)3B2.1 GBGPU、全レイヤー
    使えるGPUなし、RAM 16 GB以上3B2.1 GBCPU
    使えるGPUなし、RAM 8から16 GB1.5B1.1 GBCPU
    RAM 8 GB未満0.5B0.5 GBCPU、結果は簡素になるという警告つき

    コンパクトに量子化されたオープンソースのコーディングモデルを公式リポジトリからダウンロードし、公開されている SHA-256 で検証します。設定または --model 14b|7b|3b|1.5b|0.5b で変更できます。出典: FIRST-RUN.md。

    制限についても正直に

    得意なこと。
    そして苦手なこと。

    自分のマシンで動く小さなモデルは、プライベートで、使うのにお金がかかりません。その一方で、データセンターの最大級のモデルより遅く、できることも少なくなります。目安は次のとおりです。

    モデルが必要です

    モデルがなければ何も生成されません。初回起動で0.5から9.0 GBのモデルをダウンロードします。すでに使っているローカルのランタイムが動いている場合や、自分のAPIキーを追加した場合は不要です。

    ここで見るより時間がかかります

    ワーカーは1つのモデルを順番に使うので、仕事には数秒ではなく数分かかります。CPUだけの場合、モデルが書けるのは1秒あたり数トークンです。

    あなたが舵を取るといちばんうまくいきます

    一度に1つずつ頼み、差分を読み、ステップを承認してください。大きなアプリを一気に作るのは、小さなモデルには無理です。

    あなたのハードウェアでできること

    ハードウェア動くモデル速度向いていること
    GPUなし0.5Bまたは1.5Bのコーディングモデル、RAM 16 GBなら3B遅い、1秒あたり数トークン1ファイルの小さなタスク。待つ覚悟で。
    4から7 GBのGPU3Bのコーディングモデル、すべてGPUで実用的小さなタスク、コンポーネント、スクリプト、文章。
    7から10 GBのGPU7Bのコーディングモデル良好小から中規模のタスク、あなたが舵を取れば。
    10 GB以上、またはキー14Bのコーディングモデル、すでに使っているローカルのランタイムでもっと大きなモデル、または自分のAPIキーでクラウドモデルより速い大きめの仕事や長い計画。

    苦手なこと

    • 大きく複雑なアプリを一気に作ること
    • あなたがステップを読まず承認もしない長い仕事
    • GPUのないマシンでの速度
    • モデルなしでは何もできません: モデルがなければ出力もありません

    仕事を分け、舵を取り、承認するときにいちばんうまくいきます。タイムラインと承認モードはそのためにあります。

    ファイルはあなたのマシンから出ません。 ネットワークを使うのは初回起動時のダウンロードと、その後はあなたがオンにしたものだけです: 貸し出しモードと Code together(ペアリングした友だちと)、GitHub、自分のキーを使うクラウドのプロバイダー、URLからの拡張機能、音声モードでのブラウザの音声認識。貸し出しモードが送るのはモデルのプロンプトと回答だけです: 一度に1リクエスト、1分あたり最大20件、プロンプトは最大120,000文字で、友だちはいつでも止められます。TURNリレーは内蔵していないため、とても厳しいネットワーク同士ではつながらないことがあります。

    FAQ

    よくある質問に、
    わかりやすく。

    アカウントやAPIキーは必要ですか?

    いいえ。標準では、あなたのマシンで動くモデルを使います。キーは任意で、クラウドモデル用に自分のAPIキーを使うときだけ必要です。キーはこのマシンのキーストアに保存されます。

    ダウンロードの大きさと、初回起動にかかる時間は?

    モデルはハードウェアに応じて0.5 GBから9.0 GB、加えてランタイムに数百MBです。100 Mbit/s なら3Bのモデルで約3分、7Bで約6分。これは一度だけで、その後はモデルを読み込む時間で起動できます。

    GPUのないノートパソコンでも動きますか?

    はい、小さなモデルでCPUで動きます: RAM 16 GBなら3B、8から16 GBなら1.5B、それ未満なら0.5B。速度は遅く、1秒あたり数トークンです。小さなタスクならこなせますが、待つ覚悟が必要です。

    プロンプトの整え役は何を変えるのですか?

    計画の前に、Mel があなたのリクエストをブリーフにします: 目標、作るもの、制約、チェック、未解決の質問。あなたがブリーフを使うか、編集するか、元の文のままにするまで、仕事は待ちます。設定でオフにもできます。

    音声モードは音声をどこかに送りますか?

    音声はブラウザの音声認識を使うため、音声がブラウザ提供元のサービスに送られることがあります。Mel の読み上げは、ローカルの音声がある場合はあなたのコンピューターで作られます。完全にローカルな音声認識はまだ提供していません。

    ワーカーがコンピューターを壊すことはありますか?

    ワーカーが使えるのはワークスペースのフォルダーに限られたツールだけで、外に出ようとするパスは拒否されます。コマンドは標準でタイムアウトと出力の上限つき、ネットワークなしで実行され、承認モードではリスクのあるステップがあなたを待ちます。拡張機能は、あなたが許可した権限でサンドボックス内で動きます。

    ランチャーでセキュリティの警告が出るのはなぜ?

    コード署名のないシンプルなスクリプトなので、初回は Windows SmartScreen と macOS Gatekeeper が確認を求めます。どれも Node.js を確認して npx hivedesk@latest を実行するだけです。

    モデルをダウンロードせずに中を見られますか?

    はい: npx hivedesk --demo が台本どおりの仕事を再生します。表示されるものにはすべてデモのラベルがついています。

    削除するには?

    ~/.hivedesk/(ランタイム、モデル、設定)と、プロジェクト内の .hivedesk/ フォルダーを削除します。npm でインストールした場合は npm rm -g hivedesk も実行してください。

    あなたの準備ができたら、Mel はいつでも。

    コマンド1つで、クルーがあなたのデスクに。

    $npx hivedesk
