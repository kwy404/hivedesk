工作原理

一座 City。
连起你信任的每台机器。

你的电脑是第一栋建筑,朋友会带来他们自己的。智能体住在房间里,接下任务,在调度器选中的那台机器上思考,始终不超出所有者允许的范围。

    创建你的 City

    启动 hivedesk。你的电脑会变成一栋建筑,里面有供智能体工作的房间: Design、Code、Review、Test、Ops 和 Library。

  2. 2

    邀请朋友

    分享六个词。你们双方比对核对词,由你决定对方可以做什么,然后他的机器会在你的旁边拔地而起。

City

City 就是系统。
上面没有一样是装饰。

建筑是机器,房间是带有各自工具的地方,每个任务都会穿过这些房间直到完成。每个数字都是实测的,否则面板会注明未测量。

有规则的房间。 智能体在某个房间工作时,它的工具会被限制为该房间的工具。任务板显示每个任务、它的状态以及它所处的循环。

每个房间都写明允许什么。 面板列出房间内可用的工具、现在在场的代理和房间里的任务。

每个数字都有来源。 实时采样会注明采样时间，没有测量的就写着未测量。

真正的工作台。 资源管理器、标签页、格式化和保存，团队运行的命令都在运行日志里。

    工作台

    一个真正的代码工作台。
    文件、搜索、终端和 git。

    在团队的工作区旁边打开你选择的文件夹。每个文件夹都是一项可以撤销的授权,团队只会在你允许的地方写入。

    资源管理器和编辑器

    创建、重命名、移动和删除。标签页最多可分成三个分组,支持诊断,以及 JavaScript 和 TypeScript 的转到定义和符号。删除文件夹时,会显示其中的文件数并请你确认。

    搜索和替换

    在所有文件中搜索,支持正则表达式、区分大小写、全字匹配,以及包含或排除模式。替换前会先逐个文件显示 diff,并跳过此后有改动的文件。

    终端

    在 Windows 和 macOS 上是真正的终端。在 Linux 上需要编译它的原生部分,否则会是一个基于管道的基础终端,并会如实标注。智能体永远拿不到终端。

    源代码管理

    状态、diff、暂存、取消暂存、丢弃、提交、分支、检出、储藏和日志,都在一个面板里。

    共享终端

    让朋友观看或输入 5、15 或 60 分钟。标签页会显示共享标记和一个终止按钮,审计日志只记录字节数,从不记录内容。

    Code together

    通过同一个加密会话共享文档,双方的光标都能看到。朋友的编辑会等待你批准,新文件也一样。

    安全

    默认拒绝。
    每项权限都有名称、经过授权、有时限、有记录。

    由拥有资源的那台机器上的引擎来决定,而不是某个浏览器标签页。访客不能挑选你的模型,不能打开 shell,也看不到你没有共享的文件。

    每次安装一个身份

    一把 Ed25519 密钥,以六个指纹词的形式展示给人看。无法读取的密钥会报错,绝不会悄悄变成一个新身份。

    会作废的邀请

    六个词,66 位,一次性,10 分钟,在第一次发起的握手时作废。之后两边的屏幕显示核对词,再由你点击接受。

    授权,默认关闭

    朋友加入时,只勾选了“查看 City”。GPU、CPU、内存、存储、终端、屏幕、剪贴板和文件都是带上限的独立授权;屏幕和终端授权会在 60 分钟内结束。

    有截止时间的租约

    出借的作业持有一份由心跳续期的 15 秒租约、一个硬性截止时间和一个 token 上限。它只在出借方的本地模型上运行,绝不使用对方的云端密钥。

    哈希链式审计日志

    加入、授权、撤销、作业和远程会话,按月记录,每一行都链接到上一行。它从不保存邀请词、密钥、提示词或回答。

    端到端加密

    密钥使用 X25519 和 HKDF,每一帧使用 ChaCha20-Poly1305,每 60 分钟更换一次密钥。中继始终只传输密文。

    来自其他机器的回答不受信任。 在由朋友的 GPU 处理的轮次中产生的任何工具调用,在每种审批模式下都需要你批准,新文件也一样。

    桌面应用还是浏览器

    哪里能用什么。
    没有意外。

    桌面应用和 npx hivedesk 在你的机器上运行同一个引擎;区别只在于窗口。单独一个网页运行在浏览器的沙箱里,所以这些都做不到。

    功能桌面应用使用 npx hivedesk 的浏览器标签页仅浏览器,不安装任何东西
    GPU 上的本地模型可以可以。引擎在你机器上的 Node.js 中运行;标签页只负责显示。不可以。网页无法启动原生程序,也无法从你的磁盘加载几 GB 的模型文件。
    共享你的 GPU 和 CPU可以,关闭窗口后也行: 它会在托盘中继续运行。可以,只要标签页保持打开。节点连接在窗口中运行,而浏览器会让后台标签页变慢或冻结。不可以。没有可以共享的引擎。
    远程控制Windows,以及 X11 上的 Linux。在应用签名之前,macOS 只能查看。在基于 Chromium 的浏览器中可以查看。控制、原生剪贴板和粘贴文件由输入助手提供,和应用中一样。不可以。网页无法在你的系统上移动鼠标或按键。
    切换显示器可以。观看方提出请求,主机选择屏幕。可以,但每次浏览器都会在自己的对话框中让主机选择屏幕: 网页永远不能自行选择屏幕。不可以
    终端 (PTY)Windows 和 macOS 上可以。Linux 上在原生部分编译成功时可以,否则是一个带标注的基础终端。一样: 终端运行在引擎中。不可以。网页无法启动 shell。
    文件系统访问你添加的文件夹,使用原生文件夹选择器。同样的文件夹。你需要输入路径,因为网页没有原生文件夹选择器。只能按浏览器的规则,一次选择或拖入一个文件。
    Ctrl Alt Del从不发送到远程机器。Windows 把它留给安全登录界面,所以 hivedesk 会有意丢弃它,Win+L 也一样。从不发送。你自己的系统也会在任何网页看到它之前拦截它。不可以
    通知来自应用的系统通知。在浏览器中允许后可用,且仅限标签页打开期间;否则显示在页面中。不可以
    后台运行可以。关闭窗口后它会留在托盘中,提供打开、暂停和退出。引擎会在它的终端里继续运行,但节点需要标签页保持打开,休眠的标签页可能会让出借的作业停滞。不可以。关闭标签页就结束了。

    推荐使用桌面应用获得完整体验。应用窗口使用系统的 Web 视图;在 macOS 和 Linux 上,屏幕共享会在你基于 Chromium 的浏览器中打开,因为这些 Web 视图无法可靠地捕获屏幕。

    坦诚说明局限

    1.0 还做不到的事。
    有的是暂时,有的是有意为之。

    每一项在应用中也有标注。这里没有任何东西是为了看起来已完成而伪造的。

    节点需要一个窗口

    跨互联网时,节点连接在应用窗口或浏览器标签页中运行。无界面节点需要一个尚未构建的原生 WebRTC 组件;在同一网络中,hivedesk invite --lan 可以在终端里使用。

    没有 TURN 中继

    两个非常严格的网络之间可能连不上。hivedesk doctor --p2p 会告诉你问题出在哪一边,而同一网络中的两个节点可以使用局域网。

    还没有签名

    下载包还没有代码签名或公证。这就是 macOS 远程控制只能查看的原因,也是你的系统在首次运行前发出警告的原因。

    每个出借方一个模型

    朋友的机器只提供它已加载的模型。它从不替换所有者的模型,也从不为其他节点下载模型。

    巨型模型是实验性的

    通过加密的 p2p 连接,把一个模型汇集到朋友们的机器上运行,已经在 1.0 中,但默认关闭,速度取决于机器之间的网络连接。

    小模型很慢

    工作者轮流使用同一个模型,所以一项作业要花几分钟。只用 CPU 时,模型每秒只能写出几个 token。一口气做出大型应用,超出了它的能力。

    你的硬件能做什么

    硬件运行的模型速度适合
    没有 GPU0.5B 或 1.5B 编程模型,内存 16 GB 时可用 3B慢,每秒几个 token单个文件的小任务。需要耐心等待。
    4 到 7 GB 的 GPU3B 编程模型,完全在 GPU 上能用小任务、组件、脚本、文案。
    显存 7 到 10 GB 的 GPU,或朋友的 GPU7B 编程模型不错中小型任务,由你掌舵。
    10 GB 或以上,或者一个密钥14B 编程模型、你已经在用的本地运行环境里更大的模型,或者用你自己的 API 密钥调用云端模型更快更大的工作和更长的计划。

    你的文件留在你的电脑上。 朋友的 GPU 只能看到你发给它的作业的提示词和回答,永远看不到你的文件、工具或记忆。网络只用于你开启的功能: 朋友及其授权、GitHub、使用你自己密钥的云服务商、来自 URL 的扩展,以及语音模式下浏览器的语音识别。

    常见问题

    常见问题,
    说得明明白白。

    需要账户或 API 密钥吗?

    不需要。默认使用在你自己电脑上运行的模型,朋友会直接连接到你。密钥是可选的,只在你想用自己的 API 密钥调用云端模型时才需要;它们保存在你电脑上的密钥库里。

    朋友能看到我的文件吗?

    只有你为他勾选了“读取工作区”才可以。朋友加入时,只开启了“查看 City”。他提出的编辑会等待你批准,新文件也一样。

    我借用朋友的 GPU 时,它能看到什么?

    只有发给它的作业的提示词和回答,别的都没有: 没有文件、工具或记忆。它的所有者可以停止任何作业,而由它的回答引发的任何工具调用都需要你批准。

    我需要桌面应用吗?

    不需要。npx hivedesk 运行同一个引擎,并在你的浏览器中打开窗口。应用额外提供托盘、系统通知和文件夹选择器,并且在窗口关闭后也能继续出借。上面的表格列出了所有区别。

    有人能接管我的屏幕吗?

    没有你的点击就不能。在你允许自己的地址之前,远程屏幕一直关闭;每个请求都需要你接受,默认只能查看,每项授权都会过期,锁屏时不接受输入,一个快捷键或停止按钮就能结束一切。

    没有 GPU 的笔记本能运行吗?

    可以,在 CPU 上用小模型,但很慢: 每秒几个 token。小任务没问题。在朋友允许的情况下,借用他的 GPU 就能运行更大的模型。

    如果两个网络连不上怎么办?

    运行 hivedesk doctor --p2p。它会检查中继、你的端口和你的网络类型,并告诉你是哪一边阻断了连接。没有内置 TURN 中继;在同一网络中,请使用局域网选项。

    不下载模型也能先看看吗?

    可以: npx hivedesk --demo 会在它自己的临时文件夹里演示一座 City,每个脚本化事件都标记为演示。它从不碰你的项目。

    怎么卸载?

    删除 ~/.hivedesk/(你的身份、已知节点、运行环境、模型和你的设置)以及项目里的 .hivedesk/ 文件夹。如果是用 npm 安装的,还要运行 npm rm -g hivedesk。
