0.2.0의 새 기능

Hive City.
크루가 작은 도시가 됩니다.

이제 hivedesk는 작은 도시에서 시작합니다. 내 PC는 방이 있는 건물이고, 에이전트들이 그 안에 살며, 모든 작업은 완료될 때까지 방들을 거쳐 갑니다. 친구는 여섯 단어로 합류하고 자기 컴퓨터도 함께 데려옵니다.

도시가 곧 시스템의 상태입니다. 각 방은 허용된 도구가 정해진 실제 공간입니다. 작업 보드에는 모든 작업과 그 작업이 있는 루프가 표시됩니다.

친구는 건물입니다. 친구가 Code together의 여섯 단어로 합류하면 그 컴퓨터가 내 건물 옆에 솟아오릅니다. GPU, 모델, 그 위에 사는 에이전트도 함께요.

제한이 있는 GPU 빌리기. 에이전트가 친구의 컴퓨터에 턴 수와 분 단위 시간을 요청합니다. 빌려주는 쪽은 수락하거나, 제한을 낮추거나, 거절할 수 있습니다. 모든 턴은 집계되고, 양쪽 모두 언제든 멈출 수 있으며, 오가는 것은 프롬프트와 답변뿐입니다.

Design, Code, Review, Test. 다른 에이전트가 기준에 맞춰 diff를 검토하고, 그다음 검사가 실행됩니다. 실패하면 문제 목록과 함께 작성자에게 돌아가며, 최대 3번까지 반복한 뒤 작업이 차단됩니다. 어느 단계에서든 승인하거나 되돌려 보낼 수 있습니다.

계속 남는 에이전트. 각 에이전트에게는 완료한 일로 얻은 레벨과 XP, 도구, 그리고 편집하고 고정할 수 있는 개인 메모리가 있습니다. 모두 내 컴퓨터에 저장되므로 내일도 같은 에이전트가 돌아오고, 끝나지 않은 작업이 다시 열립니다.

계속 남는 에이전트

크루의 작업자는 모두 에이전트이며, 홈 방, 레벨과 XP(작업 10, 리뷰 4, 테스트 3, 루프 없이 끝난 작업은 5 추가), 도구, 그리고 짧은 항목 최대 40개의 메모리를 가집니다.

규칙이 있는 방

Lobby, Design, Code, Review, Test, Ops, Library. 에이전트가 방에서 일하는 동안에는 그 방의 도구만 쓸 수 있습니다. Ops는 호스트 전용이고, 확장 프로그램으로 방을 추가할 수 있습니다.

작업 버스

작업은 나에게서, Mel의 계획에서, 또는 일을 되돌려 보내는 에이전트에게서 옵니다. 쉬고 있는 에이전트는 기술, 레벨, 컴퓨터 부하에 따라 입찰합니다. 모든 담당, 이동, 판정은 다시 재생할 수 있는 이벤트입니다.

게스트와도 안전하게

컴퓨터, 에이전트, 작업의 주인이 우선합니다. 게스트의 작업은 승인 모드가 켜진 상태로 실행되며, 명령이나 삭제가 없고, Ops에서는 절대 실행되지 않습니다. 예전 데스크톱이 좋다면 --no-city로 시작하세요.

npx hivedesk --demo의 실제 스크린샷으로, 도시 시나리오를 재생합니다. 친구가 여섯 단어로 합류하고, Dev가 친구의 GPU를 세 턴 동안 빌리고, 작업이 Design, Code, Review, Test를 거쳐 완료됩니다. 데모 이벤트에는 모두 표시가 붙어 있습니다. 아직 안 되는 것: Test는 정적 검사(HTML, 링크, JS 문법, CSS, JSON)를 실행할 뿐 내 테스트 스위트를 실행하지 않으며, 빌리기는 요청마다 제한이 있고 상시 공유가 아닙니다.

    1. 01

      요청

      원하는 것을 떠오르는 대로 요청 창에 입력하세요. 말로 해도 됩니다. Ctrl Space를 누르고 있는 동안 음성 모드가 듣습니다.

    2. 02

      다듬기

      Mel이 이를 브리프로 만듭니다. 목표, 만들 것, 제약, 검사, 남은 질문까지요. 내가 사용하거나, 편집하거나, 내 문장을 그대로 두기 전까지 작업은 기다립니다.

    3. 03

      계획

      Mel은 브리프를 작업 그래프로 나누고 각 작업을 작업자에게 맡깁니다. 잘 끝난 작업은 Mel이 다시 쓰는 플레이북이 됩니다.

    4. 04

      만들기

      작업자들은 로컬 모델 하나를 번갈아 쓰며 내 작업 공간에 진짜 파일을 씁니다. 모든 쓰기는 diff이고, 명령과 삭제는 내 승인을 기다립니다.

    5. 05

      검사

      QA가 검사를 실행하고, 실패한 것은 수정 작업으로 돌려보냅니다. 페이지가 통과할 때까지요.

    6. 06

      출시

      GitHub를 연결하면 크루가 작업마다 브랜치를 만들고, 커밋하고, 푸시하고, CI 상태와 함께 풀 리퀘스트를 열 수 있습니다. 모든 동작은 먼저 계획으로 보여 주고, 내가 확인해야만 실행됩니다.

    내 컴퓨터 안에 머뭅니다

    서버는 실행할 때마다 새 비밀 토큰과 함께 127.0.0.1에만 연결됩니다. 계정도, 분석도 없습니다.

    127.0.0.1:51734/?t=a7f3c0e9

    세션 메모리

    프로젝트별, 사람별로 작고 용량이 제한된 메모, 그리고 작업마다 세션 파일 하나. 관련 있는 몇 개 항목이 다음 프롬프트에 들어갑니다. 어떤 항목이든 고정, 편집, 삭제할 수 있습니다.

    프로젝트빵집 이름은 Crumb, 색은 따뜻한 빵 껍질 톤.
    나순수 HTML과 CSS 선호, 빌드 단계 없음.
    세션작업 완료: 파일 5개, 검사 6개 중 6개 통과.

    원한다면 클라우드 두뇌도

    기본은 로컬입니다. 클라우드 모델용으로 내 API 키를 추가할 수 있고, 작업자마다 따로 정할 수도 있습니다. 키는 이 컴퓨터의 키 저장소에 보관됩니다. 그 제공자에게 보내는 프롬프트와 파일 내용은 내 컴퓨터 밖으로 나가며, 창에 그렇게 표시됩니다.

    오피스 모드

    일하는 크루를 구경하세요.

    상단 바에서 오피스 모드를 켜면 데스크톱이 작은 벌집 사무실로 바뀝니다. 모든 동작은 엔진의 실제 이벤트에서 나옵니다. 누가 생각 중인지, 누가 모델 차례를 기다리는지, 넘겨진 작업, 통과한 테스트까지요. Mel의 보드에서 메모지를 꿀벌에게 끌어다 놓으면 그 작업을 맡길 수 있습니다.

    npx hivedesk --demo로 찍은 오피스 모드의 실제 스크린샷입니다. 데모 이벤트에는 모두 데모 표시가 붙어 있습니다.

    요구 사항

    • Windows, macOS, Linux의 Node.js 20 이상.
    • 디스크: 모델용 0.5~9.0 GB, 그리고 런타임용 최대 약 0.7 GB, 한 번만.
    • 불러오는 데 필요한 여유 RAM: 모델을 GPU에 올리면 2.5 GB, CPU에서는 모델 크기에 1.5 GB를 더한 만큼(최소 4 GB). 그보다 적으면 불러오지 않으므로 컴퓨터가 멈추는 일이 없습니다.
    • GPU는 선택 사항: 대부분의 최신 그래픽 카드에서 동작하며, Apple Silicon도 됩니다.
    • 처음 실행할 때 네트워크가 필요합니다. 모델이 있는 로컬 런타임이 이미 실행 중이라면 그것을 쓰고 다운로드를 건너뜁니다.

    잘하는 것.
    그리고 못하는 것.

    내 컴퓨터의 작은 모델은 사적이고, 돌리는 데 돈이 들지 않습니다. 대신 데이터 센터의 가장 큰 모델보다 느리고 능력도 떨어집니다. 기대해도 되는 것은 이렇습니다.

    모델이 필요합니다

    모델이 없으면 아무것도 생성되지 않습니다. 처음 실행할 때 0.5~9.0 GB 모델을 내려받습니다. 이미 쓰고 있는 로컬 런타임이 실행 중이거나 내 API 키를 추가했다면 예외입니다.

    여기서 보는 것보다 느립니다

    작업자들이 모델 하나를 번갈아 쓰기 때문에, 작업에는 몇 초가 아니라 몇 분이 걸립니다. CPU만 쓰면 모델은 초당 몇 토큰을 씁니다.

    내가 방향을 잡을 때 가장 잘 됩니다

    한 번에 하나씩 부탁하고, diff를 읽고, 단계를 승인하세요. 큰 앱을 한 번에 만드는 것은 작은 모델에게는 무리입니다.

    7~10 GB GPU7B 코딩 모델좋음작은 작업과 중간 작업, 내가 방향을 잡으면.

    파일은 내 컴퓨터에 머뭅니다. 네트워크는 처음 실행할 때의 다운로드, 그리고 그 뒤에는 내가 켠 것에만 쓰입니다. 빌려주기 모드와 Code together(연결한 친구와), GitHub, 내 키를 쓰는 클라우드 제공자, URL로 받은 확장 프로그램, 음성 모드의 브라우저 음성 인식입니다. 빌려주기 모드는 모델의 프롬프트와 답변만 보냅니다. 한 번에 요청 하나, 분당 최대 20개, 프롬프트는 최대 120,000자이며, 친구는 언제든 멈출 수 있습니다. TURN 릴레이가 내장되어 있지 않아서, 아주 엄격한 네트워크 두 곳은 연결되지 않을 수 있습니다.

    FAQ

    궁금한 점에,
    쉽게 답합니다.

    계정이나 API 키가 필요한가요?

    아니요. 기본은 내 컴퓨터에서 돌아가는 모델입니다. 키는 선택 사항이며, 클라우드 모델에 내 API 키를 쓸 때만 필요합니다. 키는 이 컴퓨터의 키 저장소에 보관됩니다.

    다운로드 크기는 얼마이고, 첫 실행은 얼마나 걸리나요?

    모델은 하드웨어에 따라 0.5 GB에서 9.0 GB, 그리고 런타임에 몇백 MB가 더 필요합니다. 100 Mbit/s에서 3B 모델은 약 3분, 7B는 약 6분 걸립니다. 한 번만 하면 되고, 그 뒤에는 모델을 불러오는 시간이면 준비됩니다.

    GPU 없는 노트북에서도 돌아가나요?

    네, 작은 모델로 CPU에서 돌아갑니다. RAM 16 GB면 3B, 8~16 GB면 1.5B, 그보다 적으면 0.5B. 느려서 초당 몇 토큰입니다. 작은 작업은 되지만 기다릴 각오가 필요합니다.

    프롬프트 다듬기는 무엇을 바꾸나요?

    계획하기 전에 Mel이 내 요청을 브리프로 만듭니다. 목표, 만들 것, 제약, 검사, 남은 질문까지요. 내가 브리프를 쓰거나, 편집하거나, 원래 문장을 유지하기 전까지 작업은 기다립니다. 설정에서 끌 수 있습니다.

    음성 모드가 내 오디오를 어딘가로 보내나요?

    음성은 브라우저의 음성 인식을 쓰며, 오디오가 브라우저 제작사의 서비스로 전송될 수 있습니다. Mel의 음성 답변은 로컬 음성이 있으면 내 컴퓨터에서 만들어집니다. 완전한 로컬 음성 인식은 아직 제공되지 않습니다.

    작업자가 내 컴퓨터를 망가뜨릴 수 있나요?

    작업자는 작업 공간 폴더로 범위가 제한된 도구만 가지며, 그 밖으로 나가려는 경로는 거부됩니다. 명령은 기본적으로 시간 제한, 출력 상한, 네트워크 없음으로 실행되고, 승인 모드에서는 위험한 단계가 나를 기다립니다. 확장 프로그램은 내가 수락한 권한으로 샌드박스에서 실행됩니다.

    런처를 실행하면 왜 보안 경고가 뜨나요?

    코드 서명이 없는 단순한 스크립트라서, 처음 실행할 때 Windows SmartScreen과 macOS Gatekeeper가 확인을 요청합니다. 각 런처는 Node.js를 확인하고 npx hivedesk@latest를 실행할 뿐입니다.

    모델을 내려받지 않고 둘러볼 수 있나요?

    네. npx hivedesk --demo가 각본대로의 작업을 재생합니다. 보여 주는 모든 것에 데모 표시가 붙어 있습니다.

    어떻게 삭제하나요?

    ~/.hivedesk/(런타임, 모델, 설정)와 프로젝트 안의 .hivedesk/ 폴더를 삭제하세요. npm으로 설치했다면 npm rm -g hivedesk도 실행하세요.

    준비되면 언제든, Mel이 기다립니다.
